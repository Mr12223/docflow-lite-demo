# 开发协作规范

## 1. 模块职责

- `app.py`：只负责 Web 入口、请求校验、任务编排、结果返回
- `docflow_core.py`：负责多格式文档解析主流程
- `docflow_support.py`：负责依赖检查、安装建议、错误信息增强
- `invoice_extractor.py`：负责发票结构化规则与字段标准化
- `invoice_db.py`：负责发票记录持久化与导出
- `docflow/`：负责共享路径、环境变量配置、运行时初始化
- `scripts/`：负责批量测试、评测、数据准备脚本

## 2. 新代码放置原则

- 路由层不要直接写复杂业务规则
- 同一类能力优先放进同一模块，避免横向散落
- 与路径、环境变量、目录初始化相关的逻辑统一放进 `docflow/`
- 与评测、数据生成、批量处理相关的逻辑统一放进 `scripts/`

## 3. 命名规范

- Python 文件名使用小写下划线：`invoice_extractor.py`
- 函数名使用 `snake_case`
- 类名使用 `PascalCase`
- 常量使用全大写下划线：`DEFAULT_PDF_MODE`
- 布尔函数尽量使用 `is_` / `has_` / `should_` 前缀

## 4. 注释规范

- 注释解释“为什么这么做”，避免重复代码字面含义
- 复杂正则、OCR 合并、评分策略必须补充说明
- 公共函数必须写 docstring，说明输入、输出、异常边界
- 不在简单赋值和显而易见的流程上堆无效注释

## 5. 目录约定

- `uploads_temp/`：临时上传文件、OCR 缓存
- `reports/`：批测与评测输出
- `data/`：SQLite 等本地运行数据
- `docs/`：部署、设计、协作和论文材料

## 6. 提交前最小检查

```powershell
.\.venv\Scripts\python.exe -m py_compile app.py docflow_core.py docflow_support.py invoice_extractor.py invoice_db.py
```

如果本次改动涉及发票规则，再补跑：

```powershell
.\.venv\Scripts\python.exe .\scripts\run_invoice_evaluation.py .\发票样本\invoice_test_manifest.csv
```
